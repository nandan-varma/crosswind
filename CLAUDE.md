# CLAUDE.md

Guidance for agents working in this repository. Read it before changing code.

## What this is

Crosswind is a macOS app (AGPL-3.0-or-later, Developer ID distribution) that runs Linux GUI apps as native Mac windows. Apps come from Flathub.

## Architecture

- **Three processes.** (1) `Crosswind`, the store app (`App/Store`, SwiftUI). (2) `CrosswindHost`, the background agent (`App/Host`, AppKit accessory app, `LSUIElement`, entitlement `com.apple.security.virtualization`), embedded at `Contents/Library/Helpers` and started on demand by launchd through Mach service `dev.crosswind.host`. The store registers it with `SMAppService.agent` (`App/Store/Resources/dev.crosswind.host.plist`). (3) `CrosswindAppStub` (`App/Stub`, bundle `dev.crosswind.appstub`), a template embedded at `Contents/Resources`; per-app copies get `CrosswindAppID` later.
- **VM (host agent, Virtualization.framework).** Boots an Alpine arm64 guest: uncompressed `Image` kernel, `initramfs`, a read-only `system.erofs` system disk and a data disk. Code: `Packages/CrosswindKit/Sources/CrosswindKit/VM/`.
- **Guest daemon `crosswindd` (Rust, `guest/`).** Smithay Wayland compositor with a pixman renderer. It streams per-window damage to the host, LZ4-compressed protobuf over vsock port 5000. Schema: `proto/display.proto`.
- **Display (host, AppKit).** Each guest window is shown as a native `NSWindow`. Code: `Packages/CrosswindKit/Sources/CrosswindKit/Display/`.
- **Catalog.** Flatpak/Flathub. *Planned, not built.*

## Layout

- `App/Store`: the `Crosswind` SwiftUI store app. `App/Host`: the `CrosswindHost` agent and its entitlements. `App/Stub`: the `CrosswindAppStub` template.
- `tools/crosswindctl/`: command-line tool (swift-argument-parser). `status` is a stub.
- `Tests/CrosswindTests/`: unit tests hosted by the app.
- `Packages/CrosswindKit/`: SwiftPM library (Display, VM, Support, generated protobuf). Protobuf bindings are generated by `make proto`.
- `guest/`: Rust workspace, built inside the Lima VM `cwbuild` (Alpine). Not built on the Mac.
- `image/`: guest image build (`image/build.sh`, runs as root on Alpine).
- `proto/`: protobuf schemas.
- `spikes/`: throwaway experiments. Do not change them.
- `docs/`: ADRs and research.
- `project.yml`: XcodeGen spec. `Crosswind.xcodeproj` is generated and gitignored.

## Commands

- `make project`: generate the Xcode project.
- `make build`: build the app, `crosswindctl` and the tests.
- `make test`: run `CrosswindTests`.
- `make lint`: SwiftLint plus `swift-format lint` (check only).
- `make format`: rewrite Swift sources with `swift-format`.
- `make proto`: regenerate Swift protobuf bindings (`scripts/proto.sh`).
- `make guest`: release build of `crosswindd` in the Lima VM `cwbuild`.
- `make dev-agent`: build, then register the Debug `CrosswindHost` as a launchd user agent (`scripts/dev-agent.sh`). `make dev-agent-stop` unregisters it. Logs: `log stream --predicate 'subsystem == "dev.crosswind"'`.
- `make image`: build the guest image in the VM and copy it to `~/.cache/crosswind-img/`. *Planned: the copy step is not yet verified end to end.*

`make build` and `make test` use `helpers xcode` when it is installed and fall back to `xcodebuild`. The scheme is `Crosswind`; it also builds `crosswindctl`.

## Debug suite

1. `make project` (generates `Crosswind.xcodeproj` from `project.yml`).
2. `make test` (runs `CrosswindTests`).
3. `make lint`.
4. Optional: run the app from Xcode (Debug, scheme `Crosswind`) for a manual look.

`CrosswindKitTests` (in the package) has no sources yet.

## Conventions

- Swift 6 language mode. macOS 27 deployment target. Four-space indentation, lines up to 120 columns.
- `swift-format` (from the Xcode toolchain, `xcrun swift-format`) and SwiftLint with the root `.swift-format` and `.swiftlint.yml`. Do not add SwiftFormat.
- Every Swift source file carries `SPDX-License-Identifier: AGPL-3.0-or-later` in its first line.
- Entitlements: `com.apple.security.virtualization` and `com.apple.security.device.audio-input` (microphone), on `CrosswindHost`. The apps are not sandboxed (direct distribution).
- Signing: ad-hoc (`-`) by default. Release builds set `RELEASE_SIGN` to a Developer ID identity. Team `72CW7UW6RB`.
- No dead code, no speculative abstractions. Keep scaffolding minimal.
- Do not edit `Packages/`, `guest/`, `image/`, `proto/` or `spikes/` unless the task is about them.
- Commits and PRs carry no AI attribution lines.
