# 0005: Wire protocol: protobuf messages, length-prefixed, over vsock

Date: 2026-10-31. Status: accepted.

## Options
Protobuf (prost + swift-protobuf), FlatBuffers/Cap'n Proto, gRPC, JSON, hand-rolled binary.

## Decision
Protobuf with `proto/*.proto` as the single schema; Rust bindings generated in build.rs (prost), Swift bindings generated by `scripts/proto.sh` and committed. Framing: little-endian u32 length + message, 64 MiB cap.
Two vsock connections to avoid head-of-line blocking: display (5000: frames, input, window lifecycle) and control (5001: Flatpak operations, launch, logs, catalog). Pixels: premultiplied BGRA damage rectangles, LZ4 block compressed (lz4_flex in the guest, Compression framework `COMPRESSION_LZ4_RAW` on the host).

## Why not gRPC
It adds an HTTP/2 stack on both sides for a point-to-point local link.

## Consequences
Pixel payloads are copied once per hop (guest pixman -> LZ4 -> vsock -> decode into IOSurface). Revisit when profiling shows copy cost matters: the shared-memory route is a custom virtio device (VZCustomVirtioDevice) with a guest driver.
